# คำสั่งปฏิบัติงานสำหรับ ds (DeepSeek Agent): ตรวจสอบ วิเคราะห์ และแก้ไขการคำนวณอินดิเคเตอร์ซ้ำซ้อนและอินดิเคเตอร์ที่ไม่ถูกใช้งาน

**เป้าหมายการทำงาน:** ให้ ds เข้าไปตรวจหา ตรวจสอบ วิเคราะห์ และดำเนินการแก้ไขซอร์สโค้ดในโฟลเดอร์ `E:\BOT_FINALBOT\FINALBOT_Part1\data_evaluate\` เพื่อให้บอทคำนวณและใช้อินดิเคเตอร์อย่างถูกต้องตามหลักการของบอท

---

## 🎯 ภารกิจหลัก 2 เรื่อง (Core Objectives)

### เรื่องที่ 1: ตรวจหา ตรวจสอบ วิเคราะห์ และแก้ไข "การคำนวณอินดิเคเตอร์ซ้ำซ้อน" (Single Source of Truth - SSOT)
1. **สแกนค้นหา:** ตรวจสอบทุกไฟล์ใน `data_evaluate/orchestration/advanced_tools/` และ `market_classifier/` เพื่อหาจุดที่มีการสั่งคำนวณ EMA, RSI, MACD, ATR, ADX, Bollinger Bands หรือ Pivot Points ซ้ำซ้อนเองจาก DataFrame (เช่น การใช้ `.ewm()`, `.rolling()`, `calc_rsi` ซ้ำในโมดูลย่อย)
2. **แก้ไข:** เปลี่ยนโค้ดในโมดูลเหล่านั้น ให้ดึงค่าอินดิเคเตอร์ที่คำนวณเสร็จแล้วจาก `payload` หรือ `m5` / `m1` / `m15` dictionary ของ `indicator_store.py` (SSOT) มาใช้แทน ห้ามคำนวณซ้ำเด็ดขาด

### เรื่องที่ 2: ตรวจหา ตรวจสอบ วิเคราะห์ และแก้ไข "อินดิเคเตอร์ที่คำนวณแล้วไม่ถูกนำไปใช้งาน" (No Dead Data)
1. **สแกนค้นหา:** ตรวจสอบทุกค่าอินดิเคเตอร์ที่ `indicator_store.py` และ `structural_metrics.py` สร้างขึ้น แล้วไล่ตรวจสอบว่ามีฟิลด์ใดบ้างที่ไม่ถูกโมดูลหรือ Engine ใดๆ ดึงไปใช้เลย
2. **แก้ไข:** 
   - ลบการคำนวณฟิลด์ขยะ (Dead Data) ออกจาก `indicator_store.py` และ `structural_metrics.py`
   - ปรับการคำนวณ EMA ให้เหลือเฉพาะช่วงที่ใช้งานจริง (เช่น M5 คำนวณ [20, 50, 100, 200], M1 และ M15 คำนวณเฉพาะ [20] เท่านั้น ตัด EMA200 ของ M1 และ M15 ออก)
   - ปรับเกณฑ์ตรวจสอบจำนวนแท่งเทียนอุ่นเครื่อง (Fail-Fast Warm-up Check) ใน `indicator_store.py` ให้สอดคล้องกับความต้องการจริง (M5: ขั้นต่ำ 200 แท่ง, M1: ขั้นต่ำ 100 แท่ง, M15: ขั้นต่ำ 100 แท่ง)

## 🛠️ ขั้นตอนการปฏิบัติงานของ ds (Step-by-Step Execution Plan)

### ขั้นที่ 1: วิเคราะห์และวางแผน (Analysis)
- เปิดอ่านและตรวจสอบซอร์สโค้ดใน `data_evaluate/` ทุกไฟล์เพื่อสร้างรายการจุดซ้ำซ้อนและจุดไม่ได้ใช้งานจริง
- ระบุไฟล์และบรรทัดโค้ดที่ต้องแก้ไขอย่างชัดเจน

### ขั้นที่ 2: ดำเนินการแก้ไขโค้ด (Refactoring & Code Editing)
- ทำการแก้ไขไฟล์ `indicator_store.py`, `structural_metrics.py` และโมดูลย่อยใน `advanced_tools/` รวมถึง `market_classifier/` ตามผลการวิเคราะห์
- ตรวจสอบให้มั่นใจว่าไม่มีการเปลี่ยน Method Signature ของอินเทอร์เฟซหลัก

### ขั้นที่ 3: ตรวจสอบความถูกต้อง (Verification Process)
- **การทดสอบระบบ (กฎข้อ 13):** ทดสอบรันระบบผ่านคำสั่ง `python runner.py` เท่านั้น
- **การจัดการโปรเซส (กฎข้อ 14):** เมื่อบอทเปิดระบบและเชื่อมต่อคำนวณสำเร็จ ให้ทำการปิดโปรเซสบอททันที (`Stop-Process -Name python -Force`) ห้ามปล่อยให้บอทรันค้างในเบื้องหลัง
- **ยืนยันผล:** ตรวจสอบ Log/Console เพื่อยืนยันว่าไม่มี KeyError, SyntaxError หรือ Exception ใดๆ เกิดขึ้น
