### ไฟล์ติดตามสถานะ: `DS_PROGRESS.md`

นี่คือ "ความจำ" ของคุณข้าม step สร้างไฟล์นี้ไว้ใน root โปรเจกต์เดียวกัน รูปแบบนี้:

```
# DS PROGRESS TRACKER

LAST_COMPLETED_STEP: <หมายเลข step ล่าสุดที่ทำเสร็จสมบูรณ์>
CURRENT_STATUS: <กำลังทำอะไรอยู่ / เสร็จหรือค้างตรงไหน>
FILES_READ_SO_FAR: <ลิสต์ไฟล์ที่อ่านไปแล้วทั้งหมด>
KEY_FACTS_LEARNED:
- <ข้อเท็จจริงสำคัญที่เจอจากโค้ด ที่ step ถัดไปต้องรู้ ไม่ต้องไปอ่านซ้ำ>
- ...
OPEN_QUESTIONS_OR_UNCERTAINTIES:
- <สิ่งที่ยังไม่ชัดเจน ต้องระวังตอนเขียน>
NEXT_ACTION: <สิ่งที่ต้องทำต่อแบบเจาะจง ไม่กำกวม>
```

**กฎการใช้ progress file:**
- ก่อนทำ step ใดๆ: เปิดอ่าน `DS_PROGRESS.md` ก่อนเสมอ
- ทำ step เสร็จแล้ว: อัปเดตไฟล์นี้ทันที ก่อนจะถือว่า step นั้น "เสร็จ"
- ถ้า step ทำไม่จบในรอบเดียว (เช่น token หมด) ให้บันทึก progress ละเอียดที่สุด เพื่อให้รอบถัดไปสานต่อจากจุดเดิมได้แบบไม่หลงทาง

## ขั้นตอนการทำงาน (ทำตามลำดับ ห้ามข้าม)

### STEP 0 — สำรวจโปรเจกต์ทั้งหมด (ทำก่อนเขียนอะไรทั้งสิ้น)
- ใช้คำสั่ง list ไฟล์ (เช่น `dir /s /b` หรือเทียบเท่า) เพื่อดูโครงสร้างโฟลเดอร์ทั้งหมดของโปรเจกต์
- เปิดอ่านไฟล์สำคัญทุกไฟล์ที่เป็น `.py` ที่เกี่ยวกับ:
  - signal_gate.py (หรือไฟล์ที่ทำหน้าที่ signal gating)
  - ไฟล์ market state classifier (ไฟล์ที่ output state เช่น TRENDING_STRONG, SIDEWAY_RANGE, BREAKOUT_EMERGING, REVERSAL_FORMING ฯลฯ)
  - ไฟล์ strategy ทั้งหมด (รวม rejection_5m_pa และอื่นๆ)
  - ไฟล์ config / settings ทั้งหมด (เช่น .env.example, config.yaml, config.py)
  - ไฟล์ที่เกี่ยวกับ execution/order ส่งคำสั่งเทรด
  - README หรือเอกสารเก่าที่มีอยู่แล้วในโปรเจกต์ (ถ้ามี) — ใช้เป็น context เสริม ไม่ใช่ copy
  - ไฟล์ requirements.txt / package.json / pyproject.toml เพื่อดู dependency จริง
- จดทุกไฟล์ที่อ่านแล้วลงใน `DS_PROGRESS.md` → `FILES_READ_SO_FAR`
- สร้าง/อัปเดต `DS_PROGRESS.md` พร้อม `KEY_FACTS_LEARNED` จากการสำรวจนี้
- **ยังไม่ต้องเขียน FinalBOT.md ใน step นี้**

### STEP 1 — เขียนโครง FinalBOT.md (skeleton พร้อมหัวข้อทั้งหมด)
สร้างไฟล์ `FinalBOT.md` พร้อมหัวข้อทั้งหมดต่อไปนี้ (เขียนแค่หัวข้อ + 1 บรรทัดบอกว่า "(รอเติมเนื้อหา)" ในแต่ละหัวข้อก่อน):

```
# FinalBOT — เอกสารระบบฉบับสมบูรณ์

## ส่วนที่ 1: ภาพรวมระบบ (Mental Model)
1. ภาพรวมโปรเจกต์ใน 1 หน้า
2. แนวคิดหลักของระบบ และทำไมต้องออกแบบแบบนี้
3. Data Flow ของระบบ (ภาพรวมการไหลของข้อมูล)

## ส่วนที่ 2: Architecture จากโค้ดจริง
4. โครงสร้างไฟล์/โฟลเดอร์ทั้งหมด พร้อมหน้าที่แต่ละไฟล์
5. รายละเอียดแต่ละ Layer ของระบบ
6. Market State Classification (รายชื่อ state, ใครตัดสิน, output schema)
7. Strategy Specification Format (โครงสร้าง spec, ตัวอย่างจริงจากไฟล์ที่มี)
8. Signal Gate — เงื่อนไขปล่อย/บล็อกสัญญาณ

## ส่วนที่ 3: งานที่กำลังทำอยู่ (สำคัญที่สุดสำหรับคนต่องาน)
9. ปัญหา/งานที่ยังไม่เสร็จในปัจจุบัน
10. สถานะล่าสุดของระบบ (รันได้ไหม, ผลลัพธ์ล่าสุดเป็นอย่างไร)
11. รายการ TODO ที่ต้องทำต่อ (พร้อมระบุไฟล์ที่เกี่ยวข้อง)

## ส่วนที่ 4: กฎเหล็กของโปรเจกต์
12. ขอบเขตที่ห้ามแก้ / กฎการแก้โค้ด
13. Naming convention และค่าที่ตกลงกันไว้แล้ว (ห้ามเปลี่ยนเอง)

## ส่วนที่ 5: ภาคปฏิบัติ
14. วิธีติดตั้งและรันระบบ (คำสั่งจริง)
15. Dependencies และ Environment ที่ใช้จริง
16. ข้อจำกัดที่รู้อยู่แล้วของระบบตอนนี้
```

อัปเดต `DS_PROGRESS.md`: LAST_COMPLETED_STEP = 1

### STEP 2–14 — เติมเนื้อหาแต่ละหัวข้อ (1 หัวข้อ = 1 step โดยประมาณ)
สำหรับหัวข้อที่ 1 ถึง 16:
- เปิด `DS_PROGRESS.md` อ่านก่อนเสมอ
- เปิด `FinalBOT.md` หาหัวข้อที่ตรงกับ NEXT_ACTION
- แทนที่ "(รอเติมเนื้อหา)" ด้วยเนื้อหาจริง โดย:
  - อ้างอิงจากไฟล์/โค้ดจริงที่อ่านมาใน STEP 0 เท่านั้น
  - ถ้าเป็นหัวข้อเกี่ยวกับโค้ด ให้ยกตัวอย่าง code snippet จริงประกอบ (สั้นๆ พอให้เห็นภาพ ไม่ต้อง copy ทั้งไฟล์)
  - ถ้าเป็นหัวข้อ "งานที่กำลังทำอยู่" (หัวข้อ 9-11) ให้ระบุชื่อไฟล์ + ชื่อฟังก์ชัน/class ที่เกี่ยวข้องตรงๆ ไม่พูดกว้างๆ
  - ใช้ bullet point / ตาราง / code block ตามความเหมาะสม เพื่อให้อ่านง่ายและนำไปต่องานได้จริง
- เขียนเสร็จ 1 หัวข้อ → อัปเดต `DS_PROGRESS.md` ทันที (LAST_COMPLETED_STEP, KEY_FACTS_LEARNED, NEXT_ACTION ชี้ไปหัวข้อถัดไป)
- ทำซ้ำจนครบทุกหัวข้อ

### STEP 15 — ตรวจทานความสอดคล้อง (Consistency Pass)
- อ่าน `FinalBOT.md` ทั้งไฟล์อีกครั้งจากบนลงล่าง
- เช็คว่า:
  - ชื่อไฟล์/ฟังก์ชัน/state ที่พูดถึงในแต่ละหัวข้อ ตรงกันทั้งเอกสาร ไม่ขัดแย้งกันเอง
  - ไม่มีส่วนไหนเหลือ "(รอเติมเนื้อหา)"
  - หัวข้อ 9-11 (งานที่ทำอยู่) สอดคล้องกับหัวข้อ 6-8 (architecture) จริง
- แก้ไขจุดที่ขัดแย้งกัน
- อัปเดต `DS_PROGRESS.md`: LAST_COMPLETED_STEP = 15, CURRENT_STATUS = "เอกสารสมบูรณ์ ผ่านการตรวจทานแล้ว"
