# สรุปประเด็นที่ต้องพิจารณาปรับปรุงแก้ไข (จาก 74_FIELD Report)

**วันที่ตรวจสอบ:** 2026-08-10

จากการตรวจสอบเอกสารในแฟ้ม `74_FIELD Report` (74_FIELD_ORCHESTRATOR_TRACE_REPORT, data_evaluate_audit_report, part2_verification_report) พบประเด็นเชิงตรรกะ โครงสร้าง และโค้ดที่ต้องพิจารณาปรับปรุงหรือตัดสินใจ ทั้งหมด 7 ประเด็น ดังนี้:

## กลุ่มที่ 1: ประเด็นด้านตรรกะการคำนวณ (Logic Gaps)
1. **ความขัดแย้งของคะแนนเทรนด์ (`trend_strength_score`)**
   - **ปัญหา:** ใน `trend_engine.py` คำนวณคะแนนความแข็งแรงจากความชัน (Slope) เพียงอย่างเดียว โดยไม่ตรวจสอบทิศทาง (`trend_direction`) ทำให้ในสภาวะตลาดที่แกว่งตัวแรงแบบไม่มีทิศทาง (Direction = NONE) กลับได้คะแนนความแข็งแรงถึง 100 ซึ่งอาจทำให้ AI ตัดสินใจผิดพลาดได้

2. **แหล่งที่มาของ Pivot และ Support/Resistance ไม่ตรงกัน**
   - **ปัญหา:** `m5_pivot` ถูกคำนวณด้วยสูตร Floor Pivot ใน `indicator_store.py` ในขณะที่ `m5_support` และ `m5_resistance` ใช้หลักการ Fractal จาก `price_action_handler.py` เนื่องจากใช้คนละสูตรและคนละฐานข้อมูล จึงเกิดกรณีที่ค่า Pivot หลุดออกนอกกรอบ Support-Resistance ได้

3. **[RESOLVED] การอ้างอิงแท่งเทียนไม่สม่ำเสมอ (Pivot Point)**
   - **ปัญหาเดิม:** การคำนวณ Pivot ของ M5 ใช้ข้อมูล `iloc[-2]` ส่วน M1 กลับใช้ `iloc[-1]` ซึ่งไม่สม่ำเสมอกัน
   - **การแก้ไข:** ตรวจสอบพบว่า `data_feed` ได้ทำการ drop_forming ทิ้งไปแล้ว ดังนั้น `iloc[-1]` จึงเป็น Completed Candle เสมอ ปัจจุบันได้แก้ไขโค้ดให้ทั้ง M1 และ M5 ใช้ `iloc[-1]` เป็นมาตรฐานเดียวกันทั้งหมดเรียบร้อยแล้ว

4. **ความไม่เสถียรของ Fractal S/R (Fallback)**
   - **ปัญหา:** หากระบบหาจุด Fractal ไม่พบ จะสลับไปใช้ค่า Max/Min ของหน้าต่างข้อมูล หรือ ATR Projection แทน ซึ่งจะทำให้ค่าที่ได้เกิดการกระโดดอย่างกะทันหันเมื่อสภาวะตลาดเปลี่ยนแปลง

## กลุ่มที่ 2: ประเด็นด้านโครงสร้างข้อมูลและชื่อตัวแปร (Data Structure & Naming)
5. **[RESOLVED] ชื่อตัวแปร `last_candle` ชวนสับสน**
   - **ปัญหาเดิม:** ใน Payload มีตัวแปรชื่อ `last_candle` (ของ M1) และ `last_candle_bias` (ของ M5) ที่ไม่ระบุ Timeframe ทำให้ AI สับสน
   - **การแก้ไข:** แก้ไขโค้ดใน `orchestrator.py` เพื่อบังคับเปลี่ยนชื่อตัวแปรตอนสร้าง Text Payload เป็น `m1_last_candle` และ `m5_pa_last_candle_bias` อย่างชัดเจนแล้ว

6. **ค่า `tradeable` ปล่อยผ่านเสมอ**
   - **ปัญหา:** ปัจจุบันตัวแปรนี้ถูกตั้งเป็น True เสมอหากข้อมูลพื้นฐานครบ โดยไม่มีการกรองความเสี่ยงทิ้งตั้งแต่ในระบบ (Hard Block) ภาระการประเมินความเสี่ยงทั้งหมดจึงถูกผลักไปให้ AI เป็นผู้ประเมิน

## กลุ่มที่ 3: โค้ดตกค้างที่ไม่ได้ใช้งาน (Dead Code)
7. **[RESOLVED] ไฟล์ตกค้างจากการคัดลอกระบบเก่า**
   - **ปัญหาเดิม:** ในโฟลเดอร์ `data_evaluate/` มีโค้ดจำนวนมากที่ไม่ได้ถูกเรียกใช้งานเลยในการทำงานจริง (ไม่มีใน Execution Path)
   - **การแก้ไข:** ลบไฟล์และโฟลเดอร์ที่เป็น Dead Code ทิ้งทั้งหมดเรียบร้อยแล้ว (เช่น models/, interfaces/, pipeline.py, ฯลฯ) พร้อมปรับแก้ `orchestrator.py` และ `base_engine.py` ไม่ให้อ้างอิงถึงคลาสเก่า (ล้าง Dependency) และทดสอบรันระบบผ่านแล้ว
